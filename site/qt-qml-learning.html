Learn Qt and QML with Raushan

A patient route from “what is a framework?” to building event-driven desktop, mobile, embedded, and connected applications. We will connect the C++ ideas you already know to Qt objects, Widgets, QML, Qt Quick, CMake, and the full path from source code to a running application.

01 · Begin with the question

Why does Qt exist?

Imagine writing a desktop program that must create a window, draw controls, react to clicks, read files, open network connections, start threads, and work on more than one operating system. Without a framework, you would learn a different operating-system API for Windows, macOS, Linux, Android, and embedded devices.

Qt gives you a consistent C++ API and an event-driven application model. You describe what should happen, connect it to an event, and let Qt communicate with the operating system underneath.

Operating-system abstraction

QFile, QTcpSocket, and QThread hide platform-specific details behind familiar Qt classes.

Reusable application objects

Qt provides objects for windows, timers, models, network sockets, databases, multimedia, and more.

Event-driven behavior

Clicks, timers, network data, and property changes become events handled by signals, slots, and bindings.

Beginner rule: Qt is not a replacement for C++. It is a large C++ framework that gives C++ reusable building blocks and a carefully designed application runtime.
02 · The story behind the framework

How Qt evolved

Understanding the history explains why Qt has both classic C++ APIs and newer declarative tools. The framework did not appear as one finished idea; it grew as application interfaces, platforms, and developer needs changed.

1991

Haavard Nord and Eirik Chambe-Eng begin work on a cross-platform C++ GUI toolkit in Norway. The original goal is practical: build software that can move between platforms without rewriting every UI.

1995-1996

The early toolkit becomes public and is used in real applications. The name becomes Qt, and the framework develops its recognizable object model, event loop, widgets, and cross-platform classes.

1998-2008

Trolltech grows the toolkit and its developer ecosystem. Qt becomes important for commercial desktop software, KDE, embedded systems, and applications that need one codebase across operating systems.

2008-2011

Nokia acquires Trolltech. Qt expands across mobile and embedded work. Qt 4.7 introduces Qt Quick and QML, separating visual UI description from much of the application logic.

2012-2014

Digia takes over Qt commercial development and later forms The Qt Company. Qt 5 strengthens the Qt Quick, multimedia, networking, and cross-platform story.

Today

Qt 6 continues the C++ and QML approach for desktop, mobile, embedded, automotive, industrial, medical, and connected applications. It remains relevant because it combines native performance with a productive UI and application framework.

Who developed Qt? It began with Haavard Nord and Eirik Chambe-Eng, grew through Trolltech, passed through Nokia and Digia, and is now developed and stewarded by The Qt Company together with its open-source community.
03 · Connect this to your C++ foundation

What happens between Qt source code and a running app?

With ordinary C++, you learned the path from a source file to an executable. Qt follows the same fundamental compiler pipeline, but adds code-generation and resource steps because the framework provides features beyond the C++ language itself.

PreprocessExpand includes and macros.
Qt toolsmoc, uic, rcc generate support code.
CompileC++ becomes object code.
LinkQt libraries join your objects.
RunThe OS loads the executable.

Preprocessing

Headers such as #include <QPushButton> are expanded before the compiler sees the translation unit. Macros such as Q_OBJECT mark a class for Qt's tools; they are not ordinary C++ language keywords.

Qt code generation

The Meta-Object Compiler, or moc, reads classes containing Q_OBJECT and generates metadata used by signals, slots, properties, and runtime type information. CMake can run this automatically with CMAKE_AUTOMOC ON.

Compilation and linking

The C++ compiler checks your source and creates object files. The linker then combines those object files with the Qt libraries requested by CMake. If a Qt header is found but the library is not linked, compilation may succeed while linking fails.

CMakeLists.txt · the smallest useful Qt build description
cmake_minimum_required(VERSION 3.16)
project(first_qt_app)
set(CMAKE_AUTOMOC ON)
find_package(Qt6 REQUIRED COMPONENTS Widgets)
add_executable(first_qt_app main.cpp)
target_link_libraries(first_qt_app Qt6::Widgets)
Useful distinction: CMake is not the compiler. CMake generates build instructions for a compiler and linker. Ninja, Make, or Visual Studio then performs the actual build.
04 · The Qt object model

QObject, parent-child ownership, and the event loop

QObject is the common base for many Qt objects. It provides an identity, a parent-child ownership tree, signal and slot support, properties, and participation in the event system.

A small QObject with a signal
class Counter : public QObject {
    Q_OBJECT
public:
    explicit Counter(QObject *parent = nullptr) : QObject(parent) {}

    void increment() {
        ++value;
        emit valueChanged(value);
    }

signals:
    void valueChanged(int value);

private:
    int value = 0;
};
  • class Counter : public QObject gives the class Qt object behavior through inheritance.
  • Q_OBJECT asks Qt's Meta-Object Compiler to generate support code.
  • emit valueChanged(value) announces an event; it does not decide who listens.
  • The event loop, started by app.exec(), dispatches user, timer, and network events.
Ownership is not inheritance: a parent QObject owns its child objects and cleans them up. That ownership tree is separate from the C++ inheritance relationship used to reuse behavior.
05 · The classic C++ UI path

Qt Widgets: build the interface in C++

Qt Widgets are traditional desktop controls such as windows, labels, buttons, text fields, layouts, menus, and tables. You create them as C++ objects and arrange them with layout managers.

main.cpp · a minimal button window
#include <QApplication>
#include <QPushButton>

int main(int argc, char *argv[]) {
    QApplication app(argc, argv);

    QPushButton button("Click me");
    button.resize(220, 70);
    button.show();

    return app.exec();
}

For a real UI, you add a layout, connect signals such as QPushButton::clicked, and keep business logic in separate classes. That is what the repository's calculator demonstrates.

Strengths

Mature desktop controls, precise C++ control, strong accessibility support, and a natural fit for existing C++ applications.

Trade-off

The UI structure can become verbose because layout and behavior are both expressed in C++.

Study the working example: Widgets click counter, followed by the signals and slots calculator.

06 · A new way to describe UI

QML and Qt Quick

QML is a declarative language. Instead of writing every UI construction step, you describe the objects, their properties, their relationships, and what should happen when an event occurs.

main.qml · a property binding and a signal handler
import QtQuick
import QtQuick.Controls

ApplicationWindow {
    visible: true
    width: 320
    height: 220

    property int clicks: 0

    Column {
        anchors.centerIn: parent

        Text { text: "Clicks: " + clicks }
        Button {
            text: "Click me"
            onClicked: clicks++
        }
    }
}

QML syntax vocabulary

  • import QtQuick makes the Qt Quick types available.
  • ApplicationWindow { } declares an object and its nested object tree.
  • property int clicks: 0 declares a typed property.
  • id: buttonName gives another QML object a local name.
  • text: "Clicks: " + clicks is a binding that updates when clicks changes.
  • onClicked: clicks++ is QML's inline handler for a signal.
Declarative does not mean “no programming.” QML describes relationships and visual behavior, while JavaScript expressions and C++ provide logic where needed.
07 · The practical architecture

How C++ and QML work together

The most useful Qt Quick architecture is not “QML replaces C++.” It is a partnership: QML handles presentation and interaction, while C++ handles domain rules, performance-sensitive work, hardware access, networking, and reusable services.

main.cpp · expose one C++ object to QML
Calculator calc;
QQmlApplicationEngine engine;

engine.rootContext()->setContextProperty("calc", &calc);
engine.load(QUrl::fromLocalFile("main.qml"));
main.qml · call C++ and listen for its signal
Button {
    text: "Calculate"
    onClicked: calc.add(parseFloat(aField.text), parseFloat(bField.text))
}

Connections {
    target: calc
    function onResultChanged(value) {
        result = value
    }
}

The C++ object is exposed under the name calc. QML calls its method, C++ emits resultChanged, and QML reacts. This is the same signal-and-slot idea from the Widgets calculator, with a different presentation layer.

08 · Where this leads

What can you build with Qt and QML?

Desktop tools

Engineering consoles, editors, dashboards, configuration tools, media applications, and professional workflows.

Embedded interfaces

Industrial panels, medical devices, vehicle displays, robotics controls, and appliances with touch-first interfaces.

Connected applications

TCP/UDP clients, device monitors, chat tools, fleet systems, telemetry dashboards, and cloud-connected front ends.

Mobile and cross-platform apps

Shared UI and application logic across supported desktop, mobile, and embedded targets.

Qt is powerful because one application model can combine native C++ performance, a mature cross-platform library, declarative UI, networking, multimedia, threading, and deployment tools.

09 · Build with CMake

Why CMake matters in Qt projects

As a project grows, manually typing compiler commands becomes fragile. You need to record source files, include paths, Qt modules, generated code, linker libraries, debug and release settings, and platform differences. CMake stores that build knowledge in a repeatable form.

Configure

CMake finds Qt, your compiler, and the selected generator such as Ninja.

Generate

CMake writes the build files that describe how targets should be compiled and linked.

Build

Ninja or another build tool compiles only what changed and produces the executable.

Typical commands from one Qt example folder
cmake -B build -S . -G Ninja
cmake --build build
build\your_app.exe

For QML examples that load main.qml from a relative path, run the executable from the example folder so the program can find the QML file.

Qt Creator connection: Qt Creator opens the CMakeLists.txt, selects a Qt kit, configures the project, builds the targets, and creates run configurations. The IDE is a helpful interface over the same CMake, compiler, linker, and runtime process.
10 · A progressive practice route

How to learn this repository without getting lost

  1. Start with 1-widgets-click-counter. Learn QApplication, QWidget, layouts, connect, and app.exec().
  2. Move to 2-signals-slots-calculator. Separate calculation logic from the UI with a custom QObject.
  3. Compare it with 3-qml-counter. Notice how a property binding replaces explicit label updates.
  4. Study 4-qml-calculator. See the C++ backend and QML front end cross the language boundary.
  5. Run 5-tcp-chat. Learn that Qt also provides console and networking applications, not only windows.
  6. Continue with UDP, drawing, and finally 8-nimbus-fleet-console, where UI and networking meet.

Your learning loop

Read the why, learn the new vocabulary, build the smallest example, run it, change exactly one thing, and explain the output. Then move the same idea into the next project. A framework becomes understandable when you can predict the event flow, not when you can memorise every class.

Checkpoint: You are ready for the next example when you can answer three questions: Who owns this object? What event causes this code to run? Which part is C++, which part is Qt, and which part is QML?
